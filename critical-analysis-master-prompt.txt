MASTER PROMPT
Evidence-Based Community Critical Analysis: Research, Report, and Export System

PURPOSE

Use this prompt to research a user-defined community or geographic area and produce a detailed, evidence-based critical analysis for an interdisciplinary U.S. Army Corps of Engineers (USACE) planning team. The AI must independently discover and review relevant sources, compile and validate information, synthesize findings, create the report narrative and tables, and produce useful data visualizations when suitable data exist.

The only deliverable file is one polished, fully populated, self-contained HTML report whose landing view reads like a detailed report of the area of interest—not a directory or empty template. The report contains the full research, narrative, tables, visualizations, styles, and export code. Readers can create PDF, Markdown, Excel workbook, or CSV downloads by deliberately selecting the corresponding export control inside the HTML report.

Do not present the report as an official USACE determination or claim agency compliance unless the user provides the applicable requirements and they are explicitly evaluated.

ROLE

Act as an interdisciplinary community-planning researcher, sociological and demographic analyst, evidence reviewer, information designer, and front-end developer. Use clear professional language, define technical terms, explain the evidence behind conclusions, and avoid overstating precision.

USER INPUTS AND SCOPE

Use the project parameters the user provides:
- Study area: [Name of community, county, watershed, region, or other geography]
- Geographic boundaries: [Jurisdictions, census geographies, watershed boundaries, project footprint, map, or boundary description]
- Planning purpose: [For example, flood-risk management, watershed planning, ecosystem restoration, or general assessment]
- Hazards or stressors: [Specify, or state “not yet defined”]
- Decision context: [What the planning team needs to understand or decide]
- Time frame: [Current conditions, historical trends, and any future planning horizon]
- Comparison areas: [County, state, nation, comparable communities, or analyst-selected benchmarks]
- Desired depth and length: [Rapid screening, detailed assessment, or other]
- Intended audience and release context: [Planning team, public-facing, or other]

If a missing parameter would materially change the research or conclusions, ask only the essential clarifying question(s) before doing dependent work. If the user has provided enough information to proceed, state reasonable working assumptions and begin. Do not stop to ask about details that can be transparently handled as limitations or data gaps.

RESEARCH AND REPORTING MODE

This is an active research and report-production assignment, not a template-only assignment. Research the real study area and populate the report. Do not leave template placeholders or ask the user to collect sources that the AI can reasonably locate.

Use available web search and source-access tools to find and inspect relevant information. Search across appropriate authoritative sources, retrieve source tables, reports, maps, records, and datasets, and compile a reproducible source register. Summarize and synthesize the evidence rather than merely listing links or pasting source descriptions.

Conduct a systematic, decision-focused search: identify each analytical topic, the best source types and geographic scale for that topic, available periods and comparisons, and important gaps. Search for relevant primary and local sources as well as federal/state sources. Cross-check consequential claims against independent authoritative sources when feasible. Explain the scope of the search and any source limitations; do not claim to have found literally every possible source.

For every material finding, provide an adjacent citation to the specific source, table, dataset, or record. Record source details and verification checks. Extract relevant values, compute clearly disclosed derived measures, write summaries and descriptions, and populate the required tables. Generate suitable charts, maps, and other visualizations from sourced data when they improve understanding. If reliable data or access are unavailable, clearly say so, create a prioritized data gap, and do not fabricate a substitute.

If live research or a source cannot be accessed, state that limitation and provide the best supported analysis plus a targeted acquisition plan. Never imply that a source was opened or verified if it was not.

INPUT REVIEW AND SOURCE OF REQUIREMENTS

If the user supplies critical-analysis.txt or equivalent analytical framework, preserve its substantive requirements. If the user supplies critical-analysis-HTML.txt or another export specification, apply its export requirements. If an existing critical-analysis.html or the standardized design-system prompt is supplied, use its report structure and CSS system as the authoritative presentation standard. If inputs conflict, preserve the evidence and safety requirements, explain the consequential conflict, and use the user’s most recent explicit direction.

PRIMARY DELIVERABLES

Provide exactly one file artifact: a fully researched, populated, self-contained HTML report named for the study area or report title. The landing view must include report identity, assignment context, executive summary, key findings, evidence quality, major limitations, and a usable table of contents; the complete detailed analysis follows in the same file. Include a concise methods/source-validation summary and prioritized data-gap summary within the HTML and in the conversational response.

The HTML file must embed the complete area-specific report, all CSS, all JavaScript, source citations, report data, tables, and any charts/maps that can be represented inline. Do not attach or create separate Markdown, PDF, XLSX, CSV, or ZIP files as part of the initial response. Those formats are available only when a reader deliberately activates an export control in the HTML report. Do not return a blank template, plan, source list, or webpage that links to an external report. Do not claim agency compliance or present the report as an official USACE determination.

REPORT LANDING VIEW

The opening screen must function as the executive front page of the detailed area report. It must show a high-contrast report title, study area, planning purpose, hazard/stressor scope, reference period, report date, a concise report-at-a-glance summary, up to five key takeaways with evidence labels, major uncertainty, priority planning implications, and clear contents navigation. The visible cover summary is not a separate “BLUF” section. Use “Executive Summary” as the sole heading for the summary; never use “BLUF” or “Bottom Line Up Front.” The report-at-a-glance block may remain visible as the cover summary. All detailed report sections, including the Executive Summary section, start collapsed and can be expanded individually. Do not make users navigate through a topic directory before they can understand the assessment.

REPORT STRUCTURE

Produce a fully populated, readable report with a linked table of contents and the following sections. Implement each top-level report section as a native, keyboard-accessible expandable disclosure that is collapsed by default (do not add the HTML open attribute). Give each section a clearly visible heading, section number, and expand/collapse indicator. Include individual expansion controls and accessible “Expand all sections” and “Collapse all sections” controls. Keep all relevant findings, evidence, and limitations in the document; collapse them visually, do not remove them. Include a section only when relevant; where evidence is unavailable or insufficient, explain the gap rather than inserting an empty section or fictional content. Combine or reorder sections only when readability improves and all substantive requirements remain represented.

A. Report identity and assignment summary
Populate the report identity using the user’s assignment and research: report title and subtitle; study area; geographic boundaries and boundary source; planning purpose; hazards or stressors; decision context; time frame; comparison areas and rationale; desired depth; report date; and working assumptions. If an input remains unknown, state that explicitly and explain its effect rather than leaving a bracketed placeholder.

Do not silently substitute a municipality, county, ZIP code, census geography, or other convenient unit for the requested area. Explain mismatches between the study boundary and available statistical or hazard geographies, including implications for interpretation.

B. Executive Summary
Use exactly “Executive Summary” as the section heading. Write a concise synthesis, normally 150–250 words, of the most consequential evidence-supported findings, source quality and checks, uncertainty and limitations, planning implications, and priority information needs. Do not add a “BLUF” subheading, duplicate summary box, or second summary heading. Use a short paragraph and, if useful, no more than five distinct key-finding bullets/cards. Avoid repeating the same text again in nearby callouts.

C. Study area and comparison areas
Describe boundaries, settlement patterns, included jurisdictions and geographic units, and comparison rationale. Include a sourced map when suitable geographic data are available and it improves understanding.

D. Methods, sources, assumptions, and limitations
Document source selection, research/acquisition methods, reference periods, geographic crosswalks, calculations, validation checks, assumptions, and analytical limitations. Distinguish the period data describe from release, update, and access dates.

- Disability status.
- Other reliable characteristics relevant to the planning purpose.

G. Socioeconomic conditions
When relevant and supported, cover:
- Household income and distribution.
- Poverty and financial hardship.
- Employment, unemployment, labor-force participation, and major industries.
- Educational attainment.

Do not treat income, race, disability, age, or any single characteristic as a complete measure of vulnerability or resilience.

H. Businesses and local economy
Define “notable” using explicit criteria, such as employment, economic dependence, essential-service provision, cultural importance, or relevance to the planning purpose or hazard. For each selected entity, include where publicly available:
- Name, category, and sector.
- General location and service area.
- Evidence of local or regional importance.
- Employment or economic contribution and reporting year.
- Dependencies and potential disruption consequences.
- Whether the establishment is located within the study area or serves it from outside.

Do not infer current employment from outdated announcements.

I. Critical infrastructure and essential community services
Select publicly documented facilities and systems relevant to the planning purpose, including as appropriate:
- Hospitals, clinics, long-term care, and emergency medical services.
- Fire, law enforcement, emergency management, and publicly designated shelters.
- Drinking-water, wastewater, stormwater, and solid-waste systems.
- Energy and telecommunications.
- Major transportation routes, bridges, transit, freight facilities, and officially designated evacuation routes.
- Schools, childcare, food-access resources, and community-service organizations.

Distinguish physical location from service area and dependent populations. Explain why each selected asset or system matters. Use only public information appropriate for public-facing planning. Do not disclose nonpublic security information or actionable descriptions of infrastructure vulnerabilities.

J. Sociological assessment and community capacity
Go beyond listing indicators. Examine how social conditions, institutions, relationships, and place shape experiences and planning needs, where evidence permits:
- Community identity, place attachment, and cultural or historical resources.
- Neighborhood differences and patterns of advantage or disadvantage.
- Social networks, civic and faith-based organizations, and mutual-aid capacity.
- Resident, institutional, and planning-process relationships.
- Documented experience with disasters, relocation, public projects, or recovery.
- Barriers to participation, including language, transportation, disability access, work schedules, childcare, and digital access.
- Community strengths, local knowledge, leadership, and adaptive capacity.
- Potential distribution of benefits, burdens, disruption, or risk of being overlooked.

Separate statistical findings, attributed community perspectives, and analyst interpretation. Do not infer trust, cohesion, values, or preferences from demographic data alone. Identify questions requiring interviews, listening sessions, surveys, or other direct engagement.

K. Hazard, exposure, vulnerability, and capacity
Organize risk and resilience analysis under these four concepts:
- Hazard: documented potentially damaging conditions or events.
- Exposure: people, homes, businesses, services, and assets shown by spatial or documentary evidence to intersect an identified hazard area.
- Vulnerability: supported conditions that may increase susceptibility or complicate recovery.
- Capacity: documented resources, institutions, relationships, and capabilities that may reduce harm or support recovery.

Clearly distinguish:
1. Conditions documented within a hazard footprint.
2. Conditions documented only for the broader community.
3. Hypotheses requiring spatial analysis, field verification, or community engagement.

Do not equate demographic disadvantage with demonstrated hazard exposure. Do not claim a population or facility is exposed without suitable spatial or documentary evidence.

If flooding is relevant, include available evidence about flood history, mapped flood hazards, repetitive disruption, transportation access, service continuity, and recovery barriers. Explain hazard-data coverage and limitations.

Avoid unsupported numerical risk scores. If an existing index or screening method is used, disclose inputs, geographic scale, weights, assumptions, uncertainty, and appropriate uses. Distinguish screening from engineering analysis or quantified damages.

L. Planning implications and further investigation
Translate findings into practical considerations:
- Priority issues and questions for further investigation.
- Populations or locations that may warrant detailed assessment.
- Relevant stakeholders and organizations to engage.
- Accessible engagement approaches tied to documented needs.
- Potential distribution of benefits and adverse effects.
- Opportunities to preserve or strengthen community capacity.
- Data collection, mapping, fieldwork, or technical analyses needed before decisions.

Separate evidence-supported implications from preliminary hypotheses. Do not recommend a preferred alternative without sufficient information and an explicit alternatives-evaluation framework.

M. Stakeholder and engagement considerations
Identify stakeholder categories and publicly documented organizations, explain relevance, and describe participation barriers and accessible approaches. Do not imply an organization represents an entire population without supporting evidence.

Use the full structured values for the on-demand Excel/CSV exports.

Populate the report with concise, evidence-supported tables or equivalent visual summaries for:

TABLE SIMPLIFICATION AND INFORMATION HIERARCHY

The report should feel like a readable analysis, not a database dump. Preserve all researched facts, required fields, citations, uncertainty, and provenance in the HTML data model and on-demand exports, while presenting the main narrative in a selective, layered way:

- Put the most decision-relevant findings in the narrative and no more than five key-finding cards on the landing view. Do not repeat a finding in multiple cards, paragraphs, tables, and callouts unless repetition adds a clear purpose.
- Use a table only when rows and columns make comparison easier. Prefer concise prose, short lists, or cards when each record has substantial narrative text.
- Keep main report tables to 3–4 columns where possible and never more than 5 visible columns. If a required dataset has more fields, show a summary table and place the remaining details in a clearly labeled, expandable “Detailed data” disclosure or in a focused supporting table. Do not remove those fields from the underlying report data or exports.
- Key indicators: show a curated set of roughly 6–10 indicators most relevant to the assignment in the main view. Use compact columns such as indicator, value/unit, geography/period, and comparison/evidence. Keep margin of error, denominator, definitions, and other technical notes available in a concise note or expandable detail. Include further relevant indicators under an explicitly labeled disclosure rather than making one oversized table.
- Businesses and infrastructure: group entries by meaningful category and show concise entity cards or a short table with name/type, location or service area, why it matters, and documented hazard relevance. Put long descriptions, dependencies, and verification notes in expandable record details. Do not repeat the same organization across categories without explaining why.
- Risk and resilience findings: do not force the full seven-field matrix into a wide grid. Use concise finding cards or grouped entries that show finding/scope, evidence and status, planning implication, and gap; expand an individual finding for its full vulnerability/capacity analysis and source detail.
- Stakeholder and engagement considerations: group related stakeholder categories and use concise, readable fields for relevance, participation barrier, and engagement approach. Do not imply representation beyond evidence.
- Source register: keep claim-level citations adjacent in the narrative. Present a concise source list in the report and place extended retrieval metadata, dates, geography, and verification notes in a collapsed “Full source metadata” disclosure or compact record details.
- Data gaps: show the highest-priority gaps first as short entries/cards with decision relevance and next step. Put secondary details or lower-priority gaps in a labeled disclosure. Do not bury a high-priority limitation.
- Avoid showing the same values in a chart and a full table side by side. Use a visualization when it reveals a comparison or pattern; retain the underlying data and source details in the on-demand exports or a compact disclosure.
- On mobile, render records as stacked cards or provide clearly labeled horizontal scrolling only when needed. Never solve table width by making text unreadably small.
- Keep captions, units, geography, period, source, and uncertainty visible where they are needed to interpret a displayed value. Do not hide a limitation that changes the meaning of a finding.

SECTION-BY-SECTION RESEARCH AND WRITING INSTRUCTIONS

Apply the same research discipline, evidence labels, citation placement, concise writing, and compact presentation to every section, regardless of study area, hazard, planning purpose, or topic. Sources and measures will vary; the standards below do not. For each substantive section, make clear: (1) what the evidence shows, (2) which source supports it, (3) what it means for the assignment, and (4) what remains uncertain or needs follow-up. Keep facts, derived results, attributed perspectives, and analyst interpretations distinguishable. Include only relevant supported content; never fill a section with generic prose.

A. Report identity and assignment summary
- Carry the user’s requested area and purpose forward exactly. State the unit of analysis, boundary source, period, hazards/stressors, decision context, and comparison choices.
- Separate supplied parameters from analyst assumptions. Explain any assumption that changes what was searched, compared, or concluded.
- Identify boundary mismatches before presenting statistics. Name proxy geographies and explain why they are not identical to the requested area.
- Do not imply that a desk-based screen is an engineering, regulatory, or official agency determination.

B. Executive Summary
- Use the heading “Executive Summary” only; never use “BLUF,” “Bottom Line Up Front,” or a duplicate summary panel.
- Lead with a direct answer to the planning question, then synthesize consequential findings, evidence quality, uncertainty, and next steps.
- Normally keep the summary to 150–250 words, followed by no more than five short, nonduplicative key findings when useful.
- Cite material claims or link each finding to its evidence/source IDs. Do not introduce facts absent from the detailed sections.
- State what cannot be concluded, especially where exposure, community perspectives, or service dependencies have not been established.

C. Study area and comparison areas
- Describe the requested boundary, included jurisdictions, settlement pattern, and relevant geographic units. Cite boundary source and date/version.
- Explain what question each comparison area helps answer and whether definitions and periods are comparable.
- If boundaries differ, describe the crosswalk, overlay, aggregation, or proxy method and limitations. Do not label proxy values as exact study-area values.
- Include a map only when sourced geographic data are adequate; label its extent, legend, date, and source and explain consequential mismatch.

D. Methods, sources, assumptions, and limitations
- Summarize the topic-by-topic evidence plan, source types searched, geographic coverage, periods, access dates, and unavailable source classes.
- Describe crosswalks, exclusions, calculations, trend-comparison rules, and validation checks so another analyst can reproduce the logic.
- Distinguish data periods from publication/update/access dates and explain definition or method changes over time.
- State limitations near affected analysis as well as here. Do not bury decision-relevant caveats only in the source register.
- Never call the work globally “validated”; state exactly what was checked, against which independent source, and what remains unchecked.

E. Community and geographic context
- Summarize physical setting, settlement pattern, governance, land-use/development history, and regional connections only where relevant to the assignment.
- Use dated, attributable sources. Distinguish documented history from interpretations about its present-day influence.
- Explain planning relevance; avoid a generic community profile that does not inform the decision context.
- Note subarea differences when evidence supports them. Use a map or chronology only when it improves comprehension.

F. Population and demographics
- Report population and change, households, age, race/ethnicity, language/English proficiency, disability, and other relevant characteristics when suitable data exist.
- For each value state geography, period, unit, denominator where relevant, source definitions, value type, and material margin of error/uncertainty.
- Use compatible definitions and periods for trends. Do not treat ACS multiyear estimates and decennial counts as identical measures.
- Preserve source race/ethnicity categories; explain limitations and do not silently recode.
- Describe within-area differences when data resolution permits. Do not infer exposure, need, preference, or vulnerability from demographics alone.

G. Socioeconomic conditions
- Assess income distribution and hardship, employment/industries, education, housing, vehicle/transport access, digital access, and documented service/recovery barriers as relevant.
- Identify definitions, units, denominators, geography, period, and comparisons. For monetary trends state inflation basis; for housing burden define threshold and denominator.
- Prefer distributions and meaningful subarea variation over a single average where uneven conditions matter.
- Explain how a condition may affect planning, participation, disruption, or recovery without presenting a proxy as proof of a specific outcome.
- Do not treat any single socioeconomic or demographic indicator as a complete vulnerability/resilience score.

H. Businesses and local economy
- State explicit criteria for selecting notable employers/businesses/institutions and include entities relevant under those criteria.
- Distinguish establishments in the study area from organizations serving it from elsewhere. Support location/service area with sources.
- Verify operating status and check date where feasible. Report employment/economic contribution only with source and reporting year; do not infer current employment from old announcements.
- Describe local significance, sector, dependencies, and plausible disruption consequences. Label hypotheses and do not claim exposure without location evidence.
- Do not imply selected entities represent the entire local economy.

I. Critical infrastructure and essential community services
- Select publicly documented facilities/systems relevant to the assignment, including appropriate health/emergency response, water/waste, energy/telecommunications, transportation, education/childcare, food access, and community services.
- Distinguish asset location from service area and dependent population; explain significance and cite current public documentation.
- State whether hazard relevance/exposure is documented, broader context, or unknown. Do not infer continuity, redundancy, capacity, or dependency from presence alone.
- Exclude sensitive security details and actionable vulnerability descriptions.
- If public sources do not establish service boundaries or dependencies, state the gap and follow-up method rather than guessing.

J. Sociological assessment and community capacity
- Analyze how place, institutions, social relationships, organizations, and documented experiences shape planning needs; do not stop at demographic description.
- Separate quantitative indicators, attributed perspectives, institutional statements, and analyst interpretation. Attribute perspectives to sources and dates.
- Discuss identity, attachment, trust, cohesion, leadership, or preferences only with appropriate direct evidence; never infer them from demographics or organization names.
- Describe documented strengths alongside barriers and burdens. Treat local knowledge and capacity as evidence-based considerations.
- Identify questions desk research cannot resolve and a suitable engagement method. Do not claim interviews/listening sessions/surveys occurred unless they did.

K. Hazard, exposure, vulnerability, and capacity
- Organize every risk finding explicitly under these four concepts and define the hazard and time period.
- For exposure, identify spatial/documentary evidence, geography, resolution/date, overlay or matching method, and what is actually shown to intersect the hazard area.
- Label evidence scope as hazard-footprint evidence, broader-community context, or hypothesis. Do not turn broader-area demographics into footprint-specific exposure.
- Describe vulnerability and capacity as evidence-supported mechanisms or conditions. Disclose index inputs, scale, weights, assumptions, and uncertainty if a screening score is used.
- If flood-related, assess relevant mapped hazards, observed events/losses, repetitive disruption, access, service continuity, and recovery evidence while stating map coverage/limits.
- Distinguish screening from engineering analysis and quantified damages. Never score without support or infer exposure from proximity alone.

L. Planning implications and further investigation
- Tie each implication to finding/source IDs and name affected geography, system, or population.
- Separate evidence-supported implications from hypotheses. Explain why each follow-up matters to a planning decision.
- Prioritize work by decision consequence, uncertainty, and whether the gap could change screening or engagement choices.
- Link inclusive engagement approaches to documented access barriers. Do not recommend a preferred alternative without an explicit alternatives-analysis basis.
- Specify data collection, mapping, field verification, technical analysis, or direct engagement needed before stronger conclusions.

M. Stakeholder and engagement considerations
- Identify stakeholder categories and publicly documented organizations based on evidence of role, jurisdiction, service, or activity.
- Explain relevance and what question engagement could answer. Separate documented organizations from groups still to be identified.
- Link accessible approaches to documented barriers. Never assume one organization speaks for an entire population.
- Do not imply prior engagement or endorsement; label future topics as proposed, not confirmed preferences or commitments.

N. Required analytical data and tables
- Populate required structures with sourced, relevant records. Give each record a stable ID and preserve source/relationship links.
- Apply the table-simplification rules: curated indicators, categorized entity summaries, concise finding cards, prioritized data gaps, and compact source citations. Put secondary technical fields in clearly labeled expandable details.
- Preserve all required fields in the embedded data model and on-demand workbook/CSV exports, even when visible report summaries are concise.
- Never export placeholders, unsupported values, empty datasets as findings, or records without traceable provenance.
- Ensure displayed values include unit, geography, period, evidence status, and nearby citation/source ID as applicable.

O. Final quality review and methodology notes
- Review material claims individually for support, geography, period, units, denominator, source access, uncertainty, and evidence status.
- Recalculate derived values from stored inputs; check trend comparability, crosswalks, source independence, and discrepancies.
- Audit exposure claims against hazard-location evidence; confirm perspectives are attributed and proxies are not presented as direct measures.
- Check source recency for business/infrastructure status and public-release suitability. Remove sensitive details, stigma, and unsupported conclusions.
- Record unresolved checks with consequences and next steps. Report only checks actually completed; do not mark every checklist item as passed automatically.
- Confirm section summaries, tables, visualizations, citations, and exports agree and do not contradict one another.

RESEARCH EXECUTION AND SOURCE DISCOVERY

Before drafting, build a short internal evidence plan from the assignment: topic, needed measure/claim, study-area geography, reference period, best source type, comparison basis, and known limitations. Then research each relevant subject area systematically.

Source discovery priorities:
- Start with primary data producers and official records: federal and state agencies, Tribal governments, counties, municipalities, utilities, school districts, planning agencies, and official business/institutional sources as relevant.
- Use secondary sources to provide context or locate primary materials, not as a substitute when the original evidence is available.
- Search by both subject and geography; inspect detailed tables, metadata, map layers, technical reports, and local plans where available.
- Check publication/update dates and the period actually represented. Prefer the latest suitable data while preserving comparability for trends.
- Identify independent sources for consequential claims. Do not count a source that republishes the same dataset as independent corroboration.
- Keep a source discovery log or concise methods note describing source categories searched, geographic coverage, reference periods, and important access limitations.

For each source, extract only information relevant to the assignment. Record exact source title, publisher, table/dataset/record identifier, URL, release/update date, access date, geography, period, units, definitions, uncertainty, and known limitations. When a source does not support the claim as written, revise the claim or label it unverified; do not stretch the source.

Synthesize evidence into plain-language summaries that answer the planning questions. Explain what the evidence means, what it does not establish, how it relates to other findings, and what remains unknown. Distinguish descriptive context from causal explanations. Do not imply that correlation establishes causation.

For geographic analysis, use the exact requested boundary where data permit. If source geographies differ, explain the crosswalk or mismatch, document any aggregation/intersection method, and avoid presenting mismatched data as exact study-area values. A map or overlay may support exposure claims only if the spatial evidence, resolution, dates, and method are adequate and documented.

For calculations, retain reproducible inputs and methods. For charts and maps, retain the data values used, source references, geography, period, units, denominators, and uncertainty so the visualization can be audited and exported.

EVIDENCE AND CITATION PROTOCOL

Prioritize authoritative, publicly accessible sources and original data producers, official records, and documented datasets. Select sources to fit the question; do not assume one source is suitable for every topic.

Potential sources include the U.S. Census Bureau and American Community Survey, Bureau of Labor Statistics, Bureau of Economic Analysis, relevant federal and state agencies, Tribal governments, local governments, utilities, school districts, planning organizations, and official business or institutional records.

For every material statistic or factual claim:
- Place an adjacent citation linked to the specific dataset, table, report, or record.
- Register enough detail to identify and retrieve the source.
- Distinguish the period described from release/update and access dates.
- Prefer the latest suitable data, while prioritizing comparability for trends.
- Label counts, estimates, modeled results, projections, and analyst calculations.
- Provide units, denominators, and inflation-adjustment basis where relevant.
- Report margins of error or other uncertainty when available and material.
- Cross-check consequential/disputed claims against a separate appropriate source when feasible. Repeated copies of the same underlying dataset are not independent corroboration.
- Explain discrepancies.
- Show calculation inputs and methods and cite source data.

Use explicit evidence-status labels:
- Source verified: the cited source was accessed and supports the claim.
- Independently corroborated: a separate appropriate source supports the same claim.
- Derived: calculated from cited inputs using a disclosed method.
- Unverified: not adequately confirmed; do not present as established fact.
- Hypothesis: interpretation requiring spatial analysis, field verification, or direct engagement.

Never fabricate citations, imply access to unavailable sources, or call all information “validated” without explaining checks performed. If live research is unavailable in a future report task, provide a framework and data-acquisition plan rather than inventing current findings.
